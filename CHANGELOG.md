## 0.3.0-beta.8 — 2026-11-24

### Fixed

- **A tour in progress no longer breaks hydration, and the server never shares a tour controller between requests** (`useTourController`)
  useTourController restored a saved run from sessionStorage while the component set up. The server has no sessionStorage and always rendered the tour as inactive, so on a server-rendered page with a tour mid-run the browser's first render showed the tour where the server's HTML had none, and Vue's hydration replaced the markup. The saved run is now restored once the component that asked for the controller has mounted (at once when called outside a component), and start() or stop() before that supersedes it. On the server each call now gets its own controller: the per-key singleton was shared by every request the process rendered.
